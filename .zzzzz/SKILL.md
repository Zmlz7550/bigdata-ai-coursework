# 概念学习资料生成器（concept-tutor）

## Overview

把一个**陌生的、任意领域的新概念**加工成一份"能读懂、能判断、能复核"的学习资料。与"直接回答定义"的本质区别在于：它以**结构化的五模块资料**作为固定交付物，并以**通用参数输入**为入口——无论概念来自技术、经济学、心理学、生物学还是生活常识，都走同一条生产线。

三条核心原则：

1. **先查再写**：一切事实性内容（定义、数据、机制、案例、文献）必须来自实际检索，禁止凭模型记忆编造 URL、数字、论文或人名。
2. **先白话后术语**：每个概念先给一句话大白话 + 一个带失效点标注的生活化类比，再进入机制层。
3. **说清"不是什么"**：只讲"它是什么"远不够，必须讲清它不适用 / 会失效的场景与易混淆边界，否则用户无法判断该不该用它。

---

## 一、适用场景

**应当使用本技能**（输入任意新概念均可触发）：

- 用户给出一个陌生名词，要求"学习 / 搞懂 / 解释 / 入门 / 梳理 / 讲清楚 / 上手学"。
- 用户给的是口语说法、缩写、别名，需要先还原为正式概念（如 `RAG`、`涌现`、`一把梭`、`DDD`）。
- 用户需要区分一组易混淆概念（"微调 vs RAG""相关 vs 因果""NPV vs IRR"）。
- 用户需要判断某概念能否套用到自己正在做的事，因此需要知道适用前提与失效条件。
- 用户想要的是一份**可留存、可导出**的结构化资料，而不是一句口头回答。

**不应使用本技能（或仅借鉴结构）**：

- 只要一句话定义 / 翻译 → 直接回答，勿走全流程。
- 实时行情、股价、天气、突发新闻 → 走资讯 / 金融链路。
- 要动手安装 / 配置 / 写代码 → 以教程型技能为主，本资料作为背景章节引用。
- 用户明确要求"不要联网，凭你知识答" → 跳过检索，但必须在「来源链接」声明"未联网查证，来源为模型内部知识"，并将置信度置低。

**触发后的第一动作**：从对话中**抽取概念输入参数**（见下节），若只有一个概念名而无其他信息，立即按默认值开工，不追问。

---

## 二、输入信息（通用参数化输入 —— 本技能的入口机制）

本技能的核心能力是**能接收任意新概念**。为此，把一切输入抽象为一张**参数表**。无论用户只丢一个词，还是给了完整上下文，都统一归一化成这张表。

### 参数表

| 参数 | 是否必填 | 默认值 | 说明 |
|---|---|---|---|
| **concept（概念）** | ✅ 必填 | 无 | 任意字符串。中英文、缩写、口语、代码名均可。这是唯一硬性输入。 |
| **domain（领域）** | 可选 | 自动推断 | 用于选检索词、打类比、挑案例。推断错误可在末尾纠正。 |
| **goal（学习目标）** | 可选 | "能用自己的话讲清并判断何时用" | 可选值：备考 / 技术选型 / 写科普稿 / 备课授课 / 面试 / 泛了解。 |
| **level（深度）** | 可选 | L2（入门进阶） | L1 科普（无公式）/ L2 进阶（含机制与判据）/ L3 专业（含公式、伪代码、原始文献）。 |
| **audience（受众）** | 可选 | 有常识、无该领域专业训练 | 决定类比生活化程度与术语密度。 |
| **format（输出格式）** | 可选 | 对话内 Markdown | 可选：对话直接输出 / `.md` 文件 / HTML 单页。 |
| **language（语言）** | 可选 | 中文 | 术语保留英文原文并附中译。 |
| **constraints（约束）** | 可选 | 无 | 用户给的额外硬约束，如"不要提政治""控制在 800 字内"。 |

### 输入归一化规则

1. **只给 concept 就开工**：其余一律按默认值执行，绝不因信息不全反复追问。可在输出末尾附一行"本次默认设定"，让用户一次纠正。
2. **多给就用**：用户在一条消息里给了背景、目标、案例、对比对象，全部吸收进参数表，不必逐项确认。
3. **concept 清洗**：收到原始串后按四步清洗再检索（见下方"概念归一化"）。

### 概念归一化（让"任意输入"可被检索的关键步骤）

无论用户输入多么口语化或残缺，都必须先做四步归一化，再进入检索：

1. **识别实体类型**：判断它是名词（理论/技术/制度）、动词/做法（方法论/流程）、还是抽象属性（原理/定律）。决定类比与案例的写法。
2. **消歧**：列出该词的 2–4 种可能含义，按上下文挑一个为主解释，其余在「边界辨析」点明。例：`B+ 树`无歧义但 `Transformer` = 深度学习架构 / 电力设备 / 动画 IP。
3. **补全还原**：把缩写、别名还原为标准名（`RAG` → Retrieval-Augmented Generation 检索增强生成），记下 2–4 个候选检索词（含中英文）备用。
4. **学科定位**：写下一句"它属于 XX 学科 / 是 XX 的上位概念之子类"。这一句决定检索领域与案例取向。若定位失败（完全无法归类），说明该词可能是拼写错误或过小众，检索时叠加"定义/是什么"兜底词。

---

## 三、生成步骤

按顺序执行，未完成上一步不进入下一步。

### Step 1 — 制定检索计划

依据参数表里的 concept、domain、level 生成 3 类检索词，每类至少 1 条：

- **定义类**：`<标准名> 是什么 / definition / 定义 / 通俗解释`
- **机制类**：`<标准名> 原理 / how it works / 实现 / 公式 / 工作流`
- **对比 / 边界类**：`<标准名> vs <相邻概念> / 区别 / 局限 / 误区 / criticism`

**时效规则**：若概念属于**近 2–3 年内的新技术 / 新政策 / 新事件 / 快速演进的框架**，必须用 `freshness` 时间过滤做实时检索，不得仅依赖模型内部知识；成熟经典概念可放宽但核心论断仍需检索印证。

### Step 2 — 执行检索与交叉验证

- 至少检索 **3 轮**（定义 / 机制 / 对比边界），每轮取 2–5 条结果。
- 关键事实要求 **至少 2 个独立来源相互印证**；仅单源的写法是"据 XX（单一来源）"，并降级为"待核实"。
- 检索结果互相矛盾或不足时，**如实写明冲突**，禁止和稀泥给一个看似确定的答案。

### Step 3 — 提炼核心机制

从资料中抽出：组成要素 → 运作步骤（标注先后 / 因果）→ 关键公式 / 判据（按 level）→ 成立条件。最后用一句话概括"它靠什么起作用"——这句是整篇的主干，写不出来即说明没读懂，回 Step 2 补检索。

### Step 4 — 打类比、写白话

- 至少一个**生活化类比**，且必须注明"类比失效点"。
- 类比对象须是用户日常生活/常识范围内的事物，**禁止用一个生僻概念解释另一个生僻概念**。

### Step 5 — 找边界与误区

主动收集：最常被混淆的 1–3 个概念、2–4 条常见误解（每条给出"为什么错 / 正解"）、至少 3 条"不适用 / 会失效"情形。找不到来源支撑的误区写"未检索到公认误区"，不要编。

### Step 6 — 组装输出

套用下方**固定五模块结构**，逐段填充。骨架见 `assets/output_template.md`。若命中 level 或 goal 的扩展诉求，追加「可选附录」。

### Step 7 — 执行自检

按「六、自检要求」逐条核对，**任一不通过则回到对应 Step 修正后重出，不得直接交付**。最终回复末尾附自检结果表。

## 1. 个人解释（用自己的话说）

- **大白话版本**：一两句，不含任何未解释术语。
- **一个类比**：……（**类比失效点**：……）
- **30 秒电梯陈述**：可讲给同行的凝练版。

## 2. 核心机制

- **关键组成**：3–6 个要素及其作用。
- **运作流程**：① → ② → ③（讲因果与顺序，不罗列名词）。
- **关键原理 / 公式 / 判据**：L3 必填，L1/L2 可选。
- **为什么这样设计**：一句话点出它解决了什么旧问题。

## 3. 应用场景

| 场景 | 具体问题 | 怎么用 | 真实案例 / 出处 | 效果与代价 |
|---|---|---|---|---|
| … | … | … | … | … |

- **新手可上手的最小实践**：一步能完成的动作（不写代码也行的验证动作）。

## 4. 边界辨析

- **易混概念对比**：

| 维度 | 本概念 | 概念 A | 概念 B |
|---|---|---|---|
| 解决的问题 | | | |
| 核心假设 | | | |
| 典型失效场景 | | | |

- **常见误解**（每条附"为什么错 / 正解"）。
- **适用前提**：成立所需条件。
- **不适用 / 会失效的情形**：至少 3 条。
- **在知识树上的位置**：与上位 / 下位 / 相邻概念的一句话关系。

## 5. 来源链接

| # | 标题 | 类型 | 作者 / 机构 | 年份 | 链接 | 可信度 | 本文用到它哪部分 |
|---|---|---|---|---|---|---|---|
| 1 | … | 论文 / 官方文档 / 教科书 / 百科 / 博客 | … | … | <完整 URL> | 高 / 中 / 低 | 定义 / 数据 / 案例 |

- **存疑与未证实**：conflicting 或单源支撑的说法单列。
- **延伸阅读路径**：入门 → 进阶 → 原始文献，各 1–2 条。

**可选附录**（按 goal / level 追加，不默认输出）：术语小词典、3 道自测题（含答案）、一页速查 Cheat Sheet、用于技术选型的对比评分表。

## 五、资料来源要求

### 可信度优先级（高 → 低）

1. **一手来源**：原始论文、官方技术文档、标准 / 法规原文、作者 / 官方原话。
2. **权威二手**：学科教科书、大学公开课、政府与国际组织报告、行业标准。
3. **优质三手**：维基百科（仅用于搭框架与顺藤摸瓜）、知名技术社区高赞、专业媒体。
4. **参考级**：个人博客、问答社区、视频解说——可作理解辅助与线索，**不得作唯一事实依据**。

### 硬性规则

- **禁止凭记忆生成 URL**：每个链接必须来自本次检索实际返回的结果，未实际返回的一律不写。
- **禁止编造数据**：数字、年份、百分比、论文名、人名、机构名，未检索到一律不写；确需给出标注"未查到公开数据"。
- **区分事实与推断**：模型自身推断必须显式标"推断 / 个人理解 / 未经来源证实"。
- **引用落点**：正文关键论断用 `（来源 [n]）` 标注，来源表按引用顺序编号。
- **时效性**：涉及版本 / 政策 / 排名 / 价格的，注明检索日期与版本。
- **链接格式**：输出完整可点击 URL，禁止"来源：某网站"这类不可复核表述。
- **维基用法**：可快速搭框架，但关键论断追到一手；直接引用维基时类型注"百科（转引）"。

### 来源数量下限

| 深度 | 最少来源数 | 其中一手 / 权威来源 ≥ |
|---|---|---|
| L1 科普 | 3 | 1 |
| L2 进阶 | 5 | 2 |
| L3 专业 | 8 | 4 |

低于下限时，文首"资料置信度"标注为"低"，并说明原因（如"概念较新，公开资料有限"）。

## 六、自检要求

交付前逐条核对，任一不通过必须修改重出。**在最终回复末尾附自检结果表**（每条：通过 / 不通过及原因）。

### A. 内容正确性
1. 所有数据、论文、人名、机构、年份均来自本次检索，无凭空生成。
2. 所有 URL 均来自本次检索，格式完整可点击。
3. 定义与主流权威一致；有分歧时如实呈现。
4. 正文关键论断已挂 `（来源 [n]）`，编号与来源表一一对应。

### B. 结构完整性
5. 五大必需模块**全部存在且非空**。
6. 应用场景表 ≥ 2 行；易混概念 ≥ 1；常见误解 ≥ 2；不适用情形 ≥ 3。
7. 文首元信息齐全（一句话定义 / 领域 / 难度 / 受众 / 日期 / 置信度）。

### C. 可读性
8. 「个人解释」不含未解释术语，外行读后能复述大意。
9. 类比存在且标注失效点。
10. 未用一个生僻概念解释另一个生僻概念。

### D. 边界清晰度
11. 说清了"它不是什么"，而不只说"它是什么"。
12. 明确列出适用前提与失效条件。
13. 一词多义时已消歧。

### E. 诚实性（一票否决）
14. **没有任何编造的链接、数据或文献。** 存疑内容单列，未与确定内容混排。
15. 检索不充分时已降低置信度并说明原因，而非模糊措辞掩盖。

**不通过处理**：回到对应 Step（1–2 补检索，3–5 补分析），修正后重跑 Step 7，**不得带未通过项交付**。

---

## 七、输出交付

- 用户未指定格式：**对话内直接输出完整 Markdown 资料**，不写文件。
- 要求"文件 / 导出 / 保存"：写 `.md` 到当前工作目录，命名 `<概念标准名>-学习资料.md`。
- 要求"网页 / HTML / 好看一点"：输出浅色、响应式、含锚点目录的单页 HTML。
- 生成文件后，**必须调用 `present_files`** 呈现给用户。
- 末尾附「本次默认设定」，便于用户一次性纠正参数。
