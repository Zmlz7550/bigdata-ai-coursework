1. 个人解释（用自己的话说）

大白话版本

大模型什么都懂一点，但不懂你公司的具体规矩。Skill 就是把这些"具体规矩 + 干活步骤"写下来，打包成一个叫 SKILL.md 的文件。以后你只要说一句"按 XX 技能来做"，或模型发现你的需求命中这个技能，它就会照着这份手册一步步执行，产出符合你要求的、可复用的结果。

一个类比

Skill 就像给一位"通用员工"额外挂上的职业资格证/专长包：同样是员工，有人会做表格、有人会报税、有人会剪视频。给 AI 装一个"发邮件 Skill"，它就会发邮件；装一个"销售报表 Skill"，它就能按你们公司的格式精准出报表。

类比失效点：真人"持证"靠训练和经验积累；而 Skill 只是"运行时读入的指令文本"，本身不具备模型的参数能力，离开能执行的模型或工具它就只是一堆文字。

30 秒电梯陈述

Skill 是一种"把专家经验固化为可审查、可复用、可按需加载的过程知识"的单元：它通过 SKILL.md（YAML 元数据 + Markdown 指令）声明触发条件与执行流程，配合 scripts / references 等资源，把大模型的通用能力转化为特定场景的标准专业能力，解决"该怎么做、按什么流程做"的问题。

2. 核心机制

关键组成

  • SKILL.md（必需）：YAML 头（name、description，description 用于触发匹配）+ Markdown 指令正文。
  • scripts/（可选）：确定性可执行代码，减少反复手写。
  • references/（可选）：按需加载进上下文的技术文档/规范。
  • assets 等（可选）：模板、样例、schema 等产出素材。

运作流程（发现 → 激活 → 执行）

  1. 发现（元数据层）：运行时只扫描每个 skill 的 name + description（占用极小，约百余 token）。
  2. 激活：当用户请求与某 skill 的 description 匹配，或用户显式调用（如 /skill-name），才加载该 skill 的完整指令正文。
  3. 执行：模型遵循 skill 的流程与规则完成任务，产出由 skill 作者"塑造"而非模型通用先验的结果。

这一机制叫 Progressive Disclosure（渐进式披露）：层级 1 元数据常驻、层级 2 指令按需载入（<5k token）、层级 3 资源仅在引用时加载——从而装几十上百个 skill 也几乎不占日常 token。

关键判据 / 它与大模型的分工

核心分工：大模型决定"要做什么、理解需求"；Skill 决定"怎么去做、按什么流程做"。大模型是通用智能基础（灵活但不精准），Skill 是专项执行模块（专一、标准、精准、可复用）。

为什么这样设计

因为把整套专业流程每次都写进聊天提示词既冗长又不可复用，团队总是反复"复制粘贴同一套六步操作清单"。Skill 把专家的"一次做法"沉淀为可版本化、可审计、可随模型切换的独立单元，把 expertise 从"prompt-of-the-day"变成可 review 的产物。

新手可上手的最小实践

把你总在重复的一段流程（如"生成文章提纲→填充→语法检查→润色"）写成一份最小 SKILL.md：头里写 name 和会触发它的 description，正文用祈使句写清步骤，放进技能目录。下次直接点名调用，验证它是否按你的手册执行。

4. 边界辨析

易混概念对比

维度Skill（技能）Plugin（插件）MCP ServerSubagent
定位知识/流程指令分发打包单元连接外部世界独立 AI 实例
形态Markdown（SKILL.md）带元数据的包协议化服务器YAML 配置

一句话一份菜谱一本菜谱集连接外界的接口另一个专职 AI

常见误解

  • 误解：Skill 就是微调模型或新的模型。
    为什么错：Skill 不是 fine-tune，也没有训练参数。正解：它是"运行时读入的 Markdown 指令契约"，核心是定义流程与规则，不新增模型能力权重。
  • 误解：Skill 就是工具调用 / MCP。
    为什么错：Skill 告诉模型"做什么、按什么流程"；工具调用/MCP 给模型"真正去行动"的副作用能力。正解：常搭配使用——skill 描述流程，流程里调用 MCP/工具落地。
  • 误解：Skill 越多越好、内容能帮模型"记住"。
    为什么错：skill 正文只在激活时才加载，避免占上下文；但也要遵循渐进披露、指令精炼，否则描述含糊会误触发或体量失控。

适用前提

  • 存在一段可复用、可标准化的流程或规范（同一件事重复发生）。
  • 能写清触发条件（description）让模型/用户可靠命中。
  • 基础模型具备执行该 skill 指令所需的理解与工具调用能力。

不适用 / 会失效的情形

  1. 纯一次性任务：只为单个场景写 skill 的成本大于收益。
  2. 需要模型"会新的、参数级的技能"（如改语言能力）：只能靠微调，skill 无法替代。
  3. 需要真实副作用（查库、发信、改文件）：单独 skill 不够，需接 MCP/工具，否则"只会想不会做"。
  4. 依赖运行时外部能力不可用时：skill 引用的 scripts/schema 或平台 API 失效，执行即失败。

在知识树上的位置

Skill 是 Agent 的能力单元，与 Plugin（打包层）、MCP/工具调用（连接层）、Subagent（执行实例）同属"扩展 AI 的能力"这一族。它与 Tool/MCP 是"能力层 vs 连接层"的关系：Skill 定义做什么/怎么做，Agent 决定何时做/为何做。
