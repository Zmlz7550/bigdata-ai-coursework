1. 个人解释（用自己的话说）

大白话版本

你给普通的大模型（如聊天机器人）一个任务，它只会"说"出答案，剩下的每一步都得你来指挥；而 Agent（智能体）会自己把大目标拆成小步骤、自己决定先干什么、自己调用工具（查资料、发邮件、操作软件）去把事真做完，再给你一个结果。

一个类比

聊天机器人像前台客服——你问一句它答一句；Agent 更像一位项目助理——你说"帮我订下周去北京的机票并把行程整理成表格"，它会自己分步骤：查航班、比价格、筛条件、预订、生成表格，全程不用你一步步催。

类比失效点：真人助理有"长期记忆"和稳定的职业素养，而 Agent 受上下文窗口限制会"忘掉"早期内容，也可能犯错或陷入循环，不能完全等同于人。

30 秒电梯陈述

Agent 是以大语言模型为"大脑"，叠加感知、规划、记忆与工具调用，形成"感知—思考—行动—观察"闭环的自主执行系统，能把用户的高层目标转化为一连串由模型自主决策的具体动作。

2. 核心机制

关键组成

  • LLM（核心大脑）：负责理解目标、拆解任务、推理与总结，是整个系统的"中枢"。
  • 感知 / 环境：通过输入数据、用户消息或外部信息源了解当前状态。
  • 规划（Planning）：把复杂目标拆成可执行子任务，可动态调整。
  • 工具 / 行动（Tools/Action）：调用外部 API、搜索、文件、其他 Agent 等，产生真实副作用。
  • 记忆（Memory）：跨步骤保存状态与反馈，支撑多轮与个性化。
  • 观察（Observation）：读取工具执行结果，进入下一轮推理。

运作流程：ReAct 闭环（最主流范式）

  1. Thought（思考）：模型分析当前状态，决定下一步要做什么、调哪个工具。
  2. Action（行动）：调用选定的工具执行具体操作。
  3. Observation（观察）：拿到工具返回的真实结果。
  4. 回到第 1 步，基于新观察继续思考，直到满足目标、输出最终答案。
observation = initial_input
history = []
while True:
    thought, action, arg = llm.decide(observation, history)
    if action == "Finish":
        return thought            # 输出最终答案
    observation = execute_tool(action, arg)
    history.append((thought, action, observation))

关键判据 / 公式

判断一个系统是否是 Agent，核心看一句话："大模型是否拥有对『下一步行动』的绝对决策权。"如果行动序列由写死的 if-else/流程决定，LLM 只是文本生成器，那它本质是 Workflow 而非 Agent。

为什么这样设计

因为单纯的大模型只会"生成下一段文字"、无法接触真实世界，也容易在长任务中"凭空编造"（幻觉）。引入"工具调用 + 行动—观察闭环"让模型能查证事实、落地动作，把被动问答升级为主动执行。

新手可上手的最小实践

用一个支持工具调用的智能体平台（或 ReAct 框架），只给它一句开放性高层目标（如"调研某公司 2025 年财报并与同行对比"），观察它是否自主完成了"搜索→计算→总结"的多步流程——能自主完成即为 Agent，需你逐步喂步骤则是 Workflow。

4. 边界辨析

易混概念对比

维度Agent（智能体）Workflow（工作流）普通 LLM 聊天机器人
解决的问题需探索、多步、开放性任务规则固定、可预设的流水线单轮问答、文本生成
核心假设模型能自主推理决策"下一步"流程可预先确定、可预测用户给足指令即可
典型失效场景高容错率低、不可控时危险遇到超出预设的长尾需求长任务"失忆"、不能行动

常见误解

  • 误解：能调用工具就等于 Agent。
    为什么错：RPA 早就"能调 API/发邮件"却只算自动化脚本。正解：关键在模型是否拥有对下一步行动自主决策的权力，而非能不能调工具。
  • 误解：Agent 就是更聪明的聊天机器人。
    为什么错：聊天机器人是"被动响应"，Agent 是"主动规划+执行"。正解：核心差别在有没有感知、工具、记忆与行动闭环。
  • 误解：只要把上下文加长模型就能全记住。
    为什么错：Agent 的记忆能力仍受"上下文窗口"限制。正解：需靠记忆模块、摘要或外部存储来跨步骤保留信息。

适用前提

  • 底层 LLM 具备足够的多步推理与函数调用（tool calling）能力。
  • 任务"需要探索"：步骤或工具在运行前无法完全确定。
  • 容错率允许：出错可重来或由用户/人工纠正。

不适用 / 会失效的情形

  1. 低容错场景（自动转账、医疗诊断建议、工业控制）：Agent 的不可控与幻觉可能造成严重后果，应改用 Workflow + 硬编码校验。
  2. 规则完全固定的高频操作：用 Agent 只会更慢更贵，Workflow 效率与成本更优。
  3. 无限反馈回路风险：规划与反思不足时，Agent 可能反复调用同一工具陷入死循环。
  4. 多智能体编排失败：共享同一基座模型的多个 Agent 可能同时暴露共同缺陷，或编排故障导致全系统瘫痪。

在知识树上的位置

Agent 是 Agentic AI（智能体式人工智能）这个总概念的落地单元；它通常以大模型为底座，通过 Skill / Tool / Function Calling / MCP 获得行动能力，可单独运行也可组成多智能体系统。
